# Environment Variables Guide

This guide documents the environment variables used by the NestJS backend. Runtime validation is implemented in `src/configs/env.ts` with Zod.

## Variables

| Variable | Required | Default | Description |
|---|:---:|---|---|
| `PORT` | No | `3000` | HTTP port used by the NestJS server. |
| `NODE_ENV` | No | `development` | Runtime environment: `development`, `production`, or `test`. |
| `DATABASE_URL` | Yes | - | MongoDB connection string. Example: `mongodb://localhost:27017/threadlearn`. |
| `REDIS_URL` | No | `redis://localhost:6379` | Redis connection string for rate limiting and leaderboard cache. |
| `RATE_LIMIT_LIMIT` | No | `100` | Max requests per rate-limit window. |
| `RATE_LIMIT_WINDOW_MS` | No | `900000` | Rate-limit window in milliseconds. |
| `JWT_ACCESS_SECRET` | Yes | - | Secret for JWT access tokens. Use a long random value in production. |
| `JWT_REFRESH_SECRET` | Yes | - | Secret for JWT refresh tokens. Use a long random value in production. |
| `JWT_ACCESS_EXPIRES_IN` | No | `15m` | Access token lifetime. |
| `JWT_REFRESH_EXPIRES_IN` | No | `7d` | Refresh token lifetime. |
| `GOOGLE_CLIENT_ID` | No | - | Google OAuth client ID. Required to enable Google login. |
| `GOOGLE_CLIENT_SECRET` | No | - | Google OAuth client secret. Required to enable Google login. |
| `GOOGLE_CALLBACK_URL` | No | `http://localhost:<PORT>/api/v1/auth/google/callback` | Google OAuth redirect URI. |
| `FRONTEND_URL` | No | `http://localhost:3000` | Frontend base URL used to build verification and password reset links. |
| `SMTP_HOST` | No | - | SMTP server host. SMTP is used only when host, port, user, pass, and `MAIL_FROM_EMAIL` are all set. |
| `SMTP_PORT` | No | - | SMTP server port (e.g. `465` for secure). |
| `SMTP_SECURE` | No | `false` | Use TLS on connect (`true` for port 465). |
| `SMTP_USER` | No | - | SMTP username. |
| `SMTP_PASS` | No | - | SMTP password / Gmail app password. Whitespace is stripped automatically. |
| `MAIL_FROM_NAME` | No | `ThreadLearn` | Display name on outgoing email. |
| `MAIL_FROM_EMAIL` | No | - | From address on outgoing email. Required to enable SMTP. |
| `JUDGE0_API_URL` | No | `https://api.judge0.com` | Judge0 API URL used by code execution. |
| `JUDGE0_API_KEY` | No | - | Optional Judge0 API key. |
| `UPLOAD_DIR` | No | `./public/uploads` | Local upload directory for avatars and lesson attachments. |
| `MAX_FILE_SIZE_MB` | No | `10` | Maximum upload size in MB. |

## Local Development

Create `.env` from the template:

```bash
cp .env.example .env
```

Minimum local values:

```env
PORT=3000
NODE_ENV=development
DATABASE_URL=mongodb://localhost:27017/threadlearn
REDIS_URL=redis://localhost:6379
JWT_ACCESS_SECRET=local-access-secret-change-me
JWT_REFRESH_SECRET=local-refresh-secret-change-me
```

Start the server:

```bash
npm run start:dev
```

## CI/CD

CI should provide dummy values for build-time validation:

```env
DATABASE_URL=mongodb://localhost:27017/threadlearn
JWT_ACCESS_SECRET=test-access-secret
JWT_REFRESH_SECRET=test-refresh-secret
```

Recommended checks:

```bash
npm ci
npm run lint
npm run build
npm test
```

## Docker Runtime

`docker-compose.yml` already wires the app to MongoDB and Redis services:

```yaml
environment:
  - NODE_ENV=production
  - DATABASE_URL=mongodb://mongo:27017/threadlearn
  - REDIS_URL=redis://redis:6379
  - JWT_ACCESS_SECRET=${JWT_ACCESS_SECRET}
  - JWT_REFRESH_SECRET=${JWT_REFRESH_SECRET}
```

Production deployments must pass real secrets through environment variables or a secret manager.

## Security Notes

- Never commit `.env`.
- Rotate `JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` regularly.
- Use strong random secrets, for example values generated by `openssl rand -base64 32`.
- Ensure `UPLOAD_DIR` is mounted to persistent storage when running in Docker.
